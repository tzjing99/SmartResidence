# Maintainers

SmartResidence.

| Handle      | Areas                                  | Timezone |
| ----------- | -------------------------------------- | -------- |

## Becoming a maintainer

The path is: meaningful contributions over time, demonstrated good judgement
in PR reviews, and a nomination by an existing maintainer. There is no fixed
threshold; the bar is "would I happily ship a release with this person?".

## Decision-making

Day-to-day decisions are made by maintainers in PR review. Larger changes
(new domain modules, schema migrations affecting multiple tables, dropping a
dependency category) require an RFC in `docs/rfcs/` and at least two
maintainer approvals.

## Conflict resolution

Disagreements among maintainers are resolved by lazy consensus on the RFC
thread. If consensus cannot be reached within one week, the project lead
makes the call.
